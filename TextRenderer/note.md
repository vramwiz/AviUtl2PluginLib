# TextRenderer 共通ライブラリ設計ノート

## 目的

- SerifDrawで確立した高速な装飾文字描画を、PSD系、歌詞、字幕など他のプラグインでも利用できるようにする。
- Skiaを標準バックエンドとして積極的に利用する。
- 文字画像の生成、装飾、外接矩形化、キャッシュを共通化し、各プラグインで同じ最適化を繰り返さない。

## 依存方向

`TextRendererTypes -> TextRenderer -> TextRendererSkia -> 各プラグインのアダプター`

- 共通ライブラリからAviUtl2 SDK、SerifDraw、共有メモリ、VCLフォームを参照しない。
- プラグイン側がAviUtl2の`PIXEL_RGBA`やテクスチャへ変換する。
- Skia固有型は`TextRendererSkia`の公開APIから極力外へ出さない。
- `sk4d.dll`の探索、バージョン検査、初期化、終了は専用ランタイムユニットへ集約する。

## 公開入出力

### 入力

- Unicode文字列
- 優先順付きフォントファミリー
- サイズ、太字、斜体
- 横書き・縦書き
- 最大幅・最大高さ、揃え、字間、行間
- 本文色
- 複数の縁取り
- 複数の影、ぼかし、拡張
- 透明外周を切り詰めるか

### 出力

- ストレートアルファのRGBA 8bit画像
- 幅、高さ、stride
- レイアウト原点に対する画像外接矩形`Bounds`
- 可変幅文字、句読点、スペースを保持した文字・グリフ単位の実描画範囲`TextUnitBounds`
- 必要時だけ生成する文字・グリフ単位の独立透明画像`TextUnitImages`
- レイアウト、描画、合計時間と非透明画素数

`Bounds.Left`と`Bounds.Top`は負値を許可する。太い縁や左上方向の影が文字の論理原点より外へ出るためである。画像のピクセル`(0, 0)`は`Bounds.Left, Bounds.Top`に対応する。

`TextUnitBounds`は出力画像左上を原点とし、本文・縁・ぼかし・影を含む各グリフの実描画範囲を返す。
スペースは進行単位として空矩形を保持する。文字単位アニメーションは行幅の等分推定を行わず、この配列を利用する。
`CaptureTextUnits`を指定した場合は、同じグリフ座標から各文字だけを描いた`TextUnitImages`も返す。
拡大や移動では完成画像を矩形クリップせず、この独立画像を変形するため、隣の文字の縁・影を巻き込まない。

## 所有権とスレッド

- `Render`が返した`TTextRenderImage`は呼び出し側が所有して解放する。
- 生成後の画像は原則として不変扱いとし、セリフや設定が変わるまで再利用する。
- レンダラーインスタンスは当面スレッド間共有を保証しない。並列生成時はスレッドごとにインスタンスを持つ。
- Skiaのグローバル初期化とDLLハンドルだけをプロセス単位で参照カウントする。

## キャッシュ境界

- フォント・typeface・glyph run・paintなどSkia内部資源はレンダラーが再利用する。
- 完成RGBA画像のキャッシュは、本文と全設定をキーにする別ユニットへ分離する。
- 各プラグイン固有のUID、有効フレーム、話者情報を共通キャッシュキーへ直接含めない。
- 複数セリフ合成はSerifDraw側の責務とし、共通ライブラリは1回の要求につき1つのレイアウト画像を返す。

## 実装段階

1. 共通型と抽象レンダラーを作る。
2. SerifDrawのSkia試験実装を`TextRendererSkia`へ移し、同じ固定サンプルを表示する。
3. 文字・縁・影を含む外接矩形を計算し、その大きさだけRGBAを生成する。
4. SerifDraw側にAviUtl2アダプターを作り、4K全面転送を廃止する。
5. 日本語複数行、フォントフォールバック、改行、縦書きを実装・検証する。
6. 完成画像と中間レイアウトのキャッシュを追加する。
7. 他プラグインへ一つずつ移植し、旧描画との見た目と速度を比較する。

## 採用条件

- 基本文字、太い縁、透明合成がGDI+版と同等以上であること。
- 日本語、英数字、記号、サロゲートペア、絵文字でクラッシュしないこと。
- フォント欠落時に既定フォントへ安全にフォールバックすること。
- 複数行、縦書き、影を含めた外接矩形が欠けないこと。
- 空文字や全透明設定では空画像を安全に返すこと。
- DLLが見つからない場合は、原因を呼び出し側へ伝え、プラグイン全体を不正終了させないこと。
- Debug計測がReleaseビルドのホットパスへ残らないこと。

## 現在の判断

- 2026-08-10、Skiaを共通文字レンダラーの標準バックエンドとして積極採用する方針を決定した。
- GDI+は移行期間の比較・フォールバックとしてSerifDraw側へ残す。
- 最優先は外接矩形化。Skiaによって更新時生成は高速化したが、4K全面の`SetImageData`は約5msのままであり、共通ライブラリの出力サイズ設計で解決する。

## 2026-08-10 共通Skiaバックエンド初期実装

- `TextRendererSkiaRuntime.pas`を追加し、呼び出し側が指定した絶対パスから`sk4d.dll`を読み込む。プロセス内の参照カウントを持ち、最後の利用者が解放した時だけ共通キャッシュと明示ロード分を解放する。
- `TextRendererSkia.pas`を追加し、横書き1行、本文塗り、複数縁取り、フォントスタイル、優先フォント、透明外周切り詰めを実装した。
- Skiaの`MeasureText`へ本文paintと全outline paintを渡した結果を統合し、アンチエイリアス余白2pxを加えた外接矩形を出力する。論理ベースラインを`Bounds`として保持し、描画時は外接矩形左上がRGBA画像の`(0, 0)`になるよう移動する。
- 縦書き、複数行、字間、行間、影、揃え、最大幅・高さ、非切り詰め出力は未実装。要求された場合は設定を無視せず`ENotSupportedException`を返す。
- SerifDrawの固定サンプルを共通レンダラー利用へ置換した。検査結果は5285x403、8,519,420バイト、非透明画素1,306,231、外接矩形`(22,-392)-(5307,11)`、生成合計8.540ms。
- 従来の3840x2160、33,177,600バイトから転送候補バイト数を約74.3%削減した。横幅が5285pxなのは従来の4Kキャンバスで右側が切れていた520px文字列全体を保持したためで、外接矩形計算の異常ではない。
- 次はAviUtl2実機で全字形表示と`SetImageData (shared Skia)`時間を確認し、その後に固定文字列を共有メモリから受信したセリフへ置き換える。
- 外接矩形版はAviUtl2実機表示をユーザー確認済み。SerifDrawは固定文字列を終了し、既存共有メモリから受信した複数セリフを共通レンダラーで個別生成して縦積み合成する段階へ移行した。
- 共通レンダラーは1セリフごとの装飾画像生成だけを担当する。共有メモリ解析、有効フレーム判定、複数セリフの表示順と合成はSerifDraw側に留め、他プラグインへ固有プロトコルを持ち込まない。
