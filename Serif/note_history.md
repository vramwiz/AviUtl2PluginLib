## セリフ送受信の要点

- 送信入口は `Plugin_Module/Serif/PluginModuleSerif.pas` の `set_text`。
- 受信入口は同ユニットの `get_text`。
- 現行スクリプトの呼び出し形式は次のとおり。
  - 送信: `set_text(framerate, frame, layer, message, character, emotion, direction, aiueo, totaltime, lab, obj.id, current_frame)`
  - 受信: `get_text(layer, obj.id, current_frame, "object-v2")`
- `current_frame` は調査ログ用として渡すが、配送可否の条件には使わない。
  フレームのスキップ、巻き戻し、シーンを越えた送受信を許容する。
- 共有データは送信オブジェクトIDとメッセージUIDを保持する。未受領UIDを最初に取得した
  表示オブジェクトIDを `receiver_object` としてメッセージへ記録する。
- 受領済みUIDは、同じ表示オブジェクトの再評価でも、別の表示オブジェクトからの取得でも再配送しない。
  未受領のままならシーンを越えて保持し、別シーンの表示オブジェクトが受信できる。
- 旧AliasManager生成物の3引数 `get_text(layer, obj.id, obj.frame)` も、第2引数が数値の場合は
  表示オブジェクト形式と判別し、UIDの受領状態で配送する。
- `get_text(layer, layout, obj.id)` のように第2引数が文字列layoutの旧形式は互換経路として残す。
  新規の共通スクリプトとAliasManager生成物は4引数の`object-v2`経路を使用する。
- `set_text` は現行12引数が揃わない旧呼び出しでは共有メモリへ書き込まない。
- Git管理するスクリプトの正本は `Plugin_Module/Script/@Syncroh2_Script.obj2` とする。
  `Syncroh2_Module.dproj` のDebug / Win64ビルド時だけ、Moduleと同じAviUtl2 Script出力先へコピーする。
  コピー失敗時はPostBuildを失敗させ、Moduleとスクリプトの版ずれを残さない。

## セリフ枠の保持

- 保持値は `Plugin_Module/Serif/PluginModuleSerifCount.pas` の `get_serif_count` が管理する。
- 呼び出し形式は `get_serif_count(obj.id, obj.frame)`。
- オブジェクトごとの最終評価フレームを記録し、現在フレームが前回と同じか小さい場合に保持値を一括消去する。
- hold 中は不透明、続く fade 区間は残りカウントに応じて透明度を下げる。
- fade が 0 の場合は即時非表示にする。

## 確認済みの動作

- セリフがあるフレームでは文字と枠を表示する。
- セリフがないフレームでは文字と枠を表示しない。
- 共有メモリに残った受信済み UID を再表示しない。
- 同じ参照レイヤーを使うセリフ文字とセリフ枠が、同じ UID をそれぞれ受信できる。
- セリフ終了直後は設定された hold / fade を反映する。
- 過去フレームへ戻った直後は、以前のセリフ枠を残さない。

- Module側を変更した場合は `Syncroh2_Module.dproj` の Debug / Win64 をビルドする。
- 拡張プラグイン側を変更した場合は影響範囲に応じて `Syncroh2_Extension2.dproj` と

- セリフ文字とセリフ枠の両方について、表示中、セリフなし、終了直後、同一フレーム再評価、
  逆方向移動、正方向スキップを確認する。
- 問題が再発した場合は、プロジェクト、シーン、フレーム位置、再生方向、参照レイヤー、
  受信オブジェクト ID を記録する。
- Moduleのセリフ追跡ログは `PluginModuleSerif.pas` の `SERIF_MODULE_TRACE` で切り替える。
  Module自体は常にDebug構成で運用するため、`DEBUG` 定義をログの有効条件には使用しない。
  有効時のログは `%TEMP%\Syncroh2\Temp\Syncroh2_SerifModule.log` へ出力し、`event=set_serif` と
  `event=get_serif` をUID、レイヤー、フレーム、受信オブジェクト単位で照合する。

## 継続中の課題

- VOICEVOX入力の最小送信経路は実装・実機確認済み。
- VOICEVOX入力は、1件につき1行のセリフを複数並べて扱う。
  - 送信ボタンを一覧の上に固定し、行が増えた場合は一覧部分をスクロールする。
  - 各行の左側には、シーン別セリフ一覧と同じキャラベクターアイコンを表示する。
    選択中のキャラ名に対応する `Vector\<キャラ名>.ini` を使用し、取得できない場合だけ仮図形を表示する。
  - キャラ名からのファイル解決、更新時刻付きキャッシュ、ベクター描画は
    `SerifCharaIconRenderer.pas` へ共通化し、シーン別セリフ一覧とVOICEVOX入力で共有する。
  - 話者アイコンの左クリックで、VOICEVOX Engineの `/speakers` から取得した話者選択メニューを表示する。
    - 親項目は「キャラアイコン＋キャラ名」、サブメニューはそのキャラのtalk用感情（style）とする。
    - 現在行の感情にはチェックを表示する。
    - 選択結果は行ごとにキャラ名、`speaker_uuid`、感情名、style IDとして保持する。
    - 新しく追加した行は、直前の行の話者と感情を引き継ぐ。先頭行はVOICEVOXのstyle ID 3を規定値とし、
      存在しない環境では取得できた最初のtalk styleを使用する。
    - 送信時は行のstyle IDを `audio_query` と `synthesis` に渡し、キャラ名と感情名を既存Analyzer用の
      wav/txtファイル名にも反映する。これにより既存の流し込み経路へ選択結果が渡る。
    - `audio_query` の応答JSONへ、送信行のキャラUUID＋style IDに対応する速度・音高・抑揚・音量・
      前間・後間を上書きしてから `synthesis` へ渡す。
  - 話者アイコンの右クリックでは、現在行で選択中のキャラを固定し、そのキャラが持つ感情だけを
    フラットなメニューで表示する。現在の感情にはチェックを付け、選択結果は左クリック時と同じ経路で行へ反映する。
  - 各行の右側には確定済みのセリフを表示する。
  - セリフ表示をクリックすると、同じ領域を `TMemo` に切り替えて編集する。
  - 編集状態は一覧全体で1行だけに限定する。別行を編集する前に現在行を確定する。
  - 編集中にボタン、アイコン、一覧の空白、別タブなどへ移動した場合も、フォーカスが外れた時点で確定する。
  - 編集中の `Enter` は内容を確定し、直下に新しい行を追加して編集状態にする。
  - 編集中の `Shift+Enter` は同じセリフ内へ改行を挿入する。
  - セリフ文字は狭い画面に合わせて少し小さめに表示する。
  - 編集行と確定表示は、明示改行と表示幅による折り返しを実測して高さを広げる。
    話者アイコンの48pxを行の最低高さとして保証し、改行を保持したまま送信する。
  - `Esc` は編集前の内容へ戻してキャンセルする。
  - 空の編集行で `Del` を押すと、その行を削除して同じ位置にあった下の行を編集状態にする。

## 2026-08-05 VOICEVOX GUIのDPI対応

- VOICEVOX入力画面の実行時生成GUIは、96 DPI基準の固定値を`CurrentPPI`で換算して配置する。
- 対象はショートカット枠、1セリフ入力行、結果表示、Engine選択ボタン、設定ツールバー。
- アクセント描画の座標・当たり判定・編集欄、イントネーション／長さの列幅、共通縦型スライダーの
  描画・編集欄・当たり判定も同じDPI換算へ統一した。
- `SerifFrame`で入力フレームを親へ接続した直後に`ApplyDpi`を呼び、200%環境でも親側のDPIを使う。
- AviUtl2の親ウィンドウへ接続する前はDPI再配置を行わず、`TFrameSerif.Show`から接続後に適用する。
  これによりコンストラクタ中の`ClientWidth`参照によるVCLハンドル生成エラーを防ぐ。
- 200%表示では外形のDPI比率を維持しつつ、文字高は28pxへ固定する。話者アイコンとツールバーグリフは
  外枠より一回り小さく描画し、文字・画像だけが過度に大きくならないようにする。
- ショートカット列は56px基準へ詰める一方、話者画像は38px基準を維持して入力欄と大きさを揃える。
- アクセントのセル最小幅、文字余白、句間余白を縮め、同じ横幅へ表示できるモーラ数を増やす。
- イントネーションと長さのスライダー列は40px基準へ詰め、横方向の表示本数を増やす。
- 生成中・再生中・待機中などの状態表示も28pxへ固定し、親フォントだけがDPI拡大される差をなくす。
- アクセントグラフは全接続線を先に描き、その後に円ノードを重ねて線の端が円内へ見えないようにする。
- 完成後の一時封印として、`SerifFrame.pas`の`VOICEVOX_INPUT_TAB_ENABLED`を`False`にし、
  VOICEVOXの「入力」タブだけを非表示にする。実装とパネル登録は残し、定数を`True`へ戻せば再公開できる。

## 2026-08-06 VOICEVOX文字サイズのDPI比例対応

- 200%環境に合わせて文字高を一律28pxへ固定していたため、150%環境では周囲の寸法に対して文字だけが
  大きく見えていた。96 DPI基準を14pxとし、`CurrentPPI`に比例して文字高を計算するよう変更した。
- 150%では21px、200%では従来どおり28pxとなる。入力本文、感情名、ショートカット番号、アクセント文字、
  準備・結果表示を同じ基準へ統一した。
- 共通縦型スライダー内に残っていた28px固定も同じDPI比例へ変更し、イントネーション、長さ、音声設定の
  キャプション、数値、数値編集欄を上段と同程度の文字サイズへ統一した。
- イントネーションと長さのスライダー列幅を96 DPI基準40pxから36pxへ縮め、横スクロール量も列幅へ
  合わせた。操作領域を大きく損なわず、同じ表示幅で確認できるモーラ・音素数を増やす。
- `Syncroh2_Extension2.dproj`と`Syncroh2_Desktop.dproj`のDebug / Win64は、PostBuildを無効にして
  ビルド成功した。今回の変更によるコンパイルエラーはなく、既存警告のみ。

## 2026-08-08 台本を意識しない自動保存ライフサイクル

- 台本未関連付けの新規プロジェクトでセリフ画面を使うと、Windowsの一時領域にプロジェクト固有の
  作業台本を自動作成する。作業台本はGUID付きフォルダと排他ロックを使用し、複数のAviUtl2で共有しない。
- 起動時に一時領域を走査し、ロックされていない作業台本を異常終了などの残骸として削除する。
  稼働中の別AviUtl2がロックしているフォルダは削除しない。
- 作業台本を使用中の新規プロジェクトを初めて保存すると、保存直前コールバックで正式台本フォルダを作り、
  新しい関連付けを同じプロジェクト保存へ含める。保存後にセリフ、音声、設定を正式フォルダへ昇格する。
- 保存済みプロジェクトを同じフォルダへ別名保存した場合は、破損対策用の複製と判断して台本を維持する。
- 保存済みプロジェクトを別フォルダへ名前付き保存した場合は、別プロジェクトと判断して新しい正式台本を作る。
  元の台本を保存してから、セリフ0件の初期化済み台本へ表示とシーン同期を切り替える。
- プロジェクト保存コールバック内では関連付けの差し替えだけを完了し、UIとファイルの切り替えは1msタイマーで
  コールバック終了後へ遅延する。セリフフレームが未生成ならUIを生成せず、後の初回表示時に同期する。
- 監視欄の状態表示と「解析中」表示を1つの可変幅ラベルへ統合した。新規台本で監視先が空の場合は
  「フォルダ未設定」と短く表示する。VOICEVOX状態が空の間は右側の予約幅も解放して見切れを防ぐ。
- 自動関連付けの実機確認中は台本管理画面と内部処理を残し、ツールバーの「台本」ボタンだけを非表示にする。
  ツールバーの縮退を避けるため、他のボタンを表示してAutoSizeを確定した後に台本ボタンを隠す。
  自然な保存・読込操作の完成を確認できた段階で、台本管理UIと不要になった手動操作を削除する。

## 2026-08-06 VOICEVOX選択セリフの再編集

- 空の本文欄へ「ここにセリフを入力」の案内を表示し、未入力時の結果メッセージも同じ文言へ統一した。
- 本文欄で`F2`を押すと、AviUtl2で選択中の`セリフ入力@Syncroh2_Script`オブジェクトから
  `セリフ`、`キャラ`、`感情`を取得し、VOICEVOX入力画面の本文・話者・styleへ反映する。
- 複数選択時はフォーカス中のセリフオブジェクトを優先し、該当しなければ選択中の先頭の
  セリフオブジェクトを使う。AviUtl2の文字列に含まれるエスケープ改行は通常の改行へ戻す。
- AviUtl2の選択数APIは複数選択の列挙用で、単一選択では0を返す。単一選択はフォーカス中
  オブジェクトから直接取得し、取得できない場合だけ複数選択一覧を探索する。
- 選択中にセリフオブジェクトがない場合、または取得したキャラ・感情を現在のVOICEVOX話者カタログで
  解決できない場合は結果欄へ理由を表示する。後者でも取得できた本文は入力欄へ反映する。
- F2取得不良の切り分け用として一時診断ログを追加した。`Syncroh2_Voicevox.log`の`Reedit`行へ、
  F2受信、選択数、フォーカス、各オブジェクトの項目取得成否と本文・キャラ・感情、カタログ照合結果を記録する。

## 将来案：複数音声合成エンジン対応

### 基本方針

- Syncroh2上のキャラクターと、音声合成ソフト固有の話者を分離して管理する。
- 同じキャラクターがVOICEVOX、COEIROINK、CeVIO AI、A.I.VOICE、VOICEPEAKなど複数の音声合成ソフトに存在できる構造にする。
- 話者ショートカットでは、キャラクターではなく「エンジン＋話者＋スタイル」で構成される音声プロファイルを選択する。
- 音声プロファイル選択時に対応エンジンへ自動で切り替え、現在の文章をそのエンジンで再解析する。

### 識別情報

- `CharacterID`：Syncroh2上で同一人物を識別する。
- `EngineID`：VOICEVOXなど使用する音声合成エンジンを識別する。
- `VoiceProfileID`：エンジン固有の話者、製品、スタイルを識別する。
- 同名の話者・スタイルが複数エンジンに存在しても、`EngineID + VoiceProfileID`で区別する。

### 設定の分離

- 話速、音高、抑揚、音量、前後無音などは可能な範囲で共通設定として扱う。
- アクセント、モーラ音高、音素長、F0、プロソディ、感情、声質、プリセットなどはエンジン固有設定として保持する。
- エンジンごとに対応機能を返す機能一覧を用意し、対応している設定ページだけをツールバーへ表示する。
- エンジン間で内部構造が異なるアクセント情報は直接移植せず、切り替え後のエンジンで文章を再解析する。

### エンジン切り替え

1. 実行中の生成・再生を停止する。
2. 選択されたエンジンを必要に応じて起動・接続する。
3. 話者とスタイルを選択する。
4. 現在の文章を新しいエンジンで解析する。
5. 音声プロファイルごとの共通設定と固有設定を復元する。
6. 対応機能に合わせて設定ページを再構築する。

### セリフへの保存情報

- 将来の再編集では、`CharacterID`、`EngineID`、`VoiceProfileID`、`StyleID`、共通設定、エンジン固有設定を保存する。
- 現在のキャラクター名＋感情名だけを持つ既存データは、従来のVOICEVOXプロファイルへ割り当てる互換処理を用意する。
- 使用エンジンが未導入・起動不能の場合は、セリフ情報を失わずに不足エンジンを表示し、別プロファイルへの置換を可能にする。

### UI案

- 話者アイコンに小さなエンジン名またはエンジンバッジを表示する。
- 共通設定は現在の操作体系を維持し、エンジン固有設定だけを差し替える。
- 実装時はエンジン別処理をGUIへ直接追加せず、共通インターフェイスを持つエンジンアダプターとして分離する。
- 最初の拡張候補はVOICEVOX互換エンジンの一般化、次にローカルHTTP APIを持つCOEIROINKとする。

  所有中の`HGLOBAL`を直接共有せず、`OleDuplicateData`でドロップ先用に複製し、二重解放と再利用を防止する。

## 将来案：新セリフ表示のアニメーション

> 2026-08-17時点の検討内容。未実装であり、仕様確定前にコード変更しない。

### UIの分類

- 現在の大分類「セリフ」「配役」「枠」に、4つ目の大分類として「アニメーション」を追加する案とする。
- アニメーションは時間軸を持ち、フォントや色などの静的なセリフ外観とは責務が異なるため、
  セリフの小分類には入れない。
- アニメーション内の中分類は「表示前」「表示中」「表示後」とする。
- 各中分類の小分類では、効果名をコンボボックスなどの文字で表示する。効果はアイコンだけでは意味が
  伝わりにくく、将来増える可能性もあるため、無理にアイコン化しない。
- 各コンボボックスの先頭項目は「なし」とし、通常表示を表す。効果が「なし」の場合は時間や強さなどの
  無効な詳細設定を隠す案とする。
- 同一本文を複数配役が話す場合の均等クリッピングは固定仕様であり、アニメーション設定内にも
  縦／横などの並び方設定は設けない。

### 時間区分

- セリフ開始フレームを表示前アニメーションの開始とする。「表示前」はオブジェクト開始より前ではなく、
  通常表示へ到達する前の区間を意味する。
- 表示前が完了した時点から、セリフ終了までを表示中とする。表示前に使用したフレーム数だけ、
  表示中の開始は後ろへ移動する。
- セリフ終了後に表示後アニメーションを開始し、設定時間を使って消失させる。
- 表示前が「なし」ならセリフ開始時に通常表示、表示中が「なし」なら静止、表示後が「なし」なら
  セリフ終了時に即座に消す。すべて「なし」なら現在と同じ通常表示になる。

### 表示前の上限

- セリフ開始と同時に音声も始まるため、表示前が長いと本文表示が発話へ追いつかず読みづらくなる。
  表示前には絶対時間とセリフ時間に対する割合の両方で上限を設ける案とする。
- 暫定案は絶対上限0.5秒、かつセリフ時間の25%以内とし、実際の表示前時間は設定値を含むこれらの
  最小値とする。数値は実機確認後に調整する。
- タイプライターは特殊効果として扱うが、長文でも短時間で全文表示を完了させる。暫定目安は
  0.15～0.35秒、最大0.5秒程度とし、必要なら1フレームで複数文字を表示する。

### 新しいセリフによる中断

- 表示後の途中で別本文の新しいセリフが開始した場合、古いセリフの表示後アニメーションは打ち切り、
  古い表示を消して新しいセリフの表示前アニメーションを開始する。
- 古いセリフの終了と新しいセリフの開始が同じフレームの場合も、新しいセリフの表示前を優先する。
- 同じ本文を別配役が同時に送った場合は別セリフへの切替ではなく、現在の同時発話へ配役が加わったものと
  して扱う。受信件数だけでは表示前を再開せず、表示本文の変化を切替判定の中心にする。

### アニメーションの合成順

- 表示前・表示中・表示後がそれぞれ独自に文字を再描画すると、表示中で変形した文字が表示後の開始時に
  通常字形へ戻るなどの不連続が起きる。そのため共通の文字状態を順番に加工する構造とする。
- 表示中アニメーションはセリフ開始から表示後の終了まで常に現在時刻で評価し、停止させない。
- 基本順序は「基本文字レイアウト → 表示中アニメーション → 表示前または表示後の追加加工 → 最終描画」
  とする。表示後は表示中の最終状態を一度だけ引き継ぐのではなく、進行し続ける表示中の現在状態へ
  毎フレーム消失加工を加える。
- 共通の描画状態には、文字ごとの位置、回転、拡大率、色、不透明度、表示状態、ぼかし、クリップ範囲などを
  持たせる案とする。不透明度は乗算、移動・回転・拡大は変換合成、クリップは範囲の積など、項目ごとの
  合成規則を明示する。
- タイプライターは完成画像の単純な横クリップではなく、論理上の文字順で表示対象を決める。表示中で
  文字が移動していても、先頭から何文字表示するかという順序は維持する。
- 同時発話では、共通レイアウトへ表示中の字形・位置変化を一度適用し、同じ状態を配役別スタイルで描画、
  均等クリッピングで合成した後、表示前または表示後を追加適用する案とする。配役ごとに文字位置を
  変えず、色の分割境界を維持する。

### シークと途中再生

- 先頭から連続再生した場合の本来の動きを保証する。
- 途中再生やシークでは、少なくとも表示が消えたり壊れたりしないことを保証する。フェード、文字数、
  周期的な揺れなど現在フレームから直接計算できる効果は、途中再生でも該当時刻の状態を表示する。
- 表示中の基準時間は「現在フレーム－セリフ開始フレーム」とし、表示後の間も進める。
- 物理演算、粒子、過去フレームからの速度蓄積など履歴依存の効果は、固定シードによる再現、現在時刻からの
  近似、または静止状態へのフォールバックを検討する。完全な運動履歴までは保証しない。
- AviUtl2からフレームが常に先頭から順番に要求されるとは限らないため、可能な効果は前フレームの
  可変状態へ依存せず、現在フレームから決定できる設計を優先する。

### 効果候補

- 表示前候補：なし、フェードイン、スライドイン、ズームイン、ポップイン、ワイプイン、ブラーイン、
  高速タイプライター、文字フェードイン、文字せり上がり、回転イン、バウンドイン。
- 表示中候補：なし、ふわふわ、ゆらゆら、呼吸、鼓動、波打ち、文字ジャンプ、震え、強調振動、
  色変化、明滅、光沢、グリッチ、ランダム揺れ。
- 表示後候補：なし、フェードアウト、スライドアウト、ズームアウト、拡大アウト、ワイプアウト、
  ブラーアウト、文字フェードアウト、文字落下、文字散開、崩壊、回転アウト、グリッチアウト、
  フラッシュアウト。
- 最初の実装候補は、表示前を「なし／フェード／スライド／ズーム／タイプライター」、表示中を
  「なし／ふわふわ／呼吸／波打ち／震え」、表示後を「なし／フェード／スライド／ズーム／ブラー」
  に絞る。スライドの方向などは別効果として列挙せず、効果選択後の詳細項目とする。
- 表示中の震え、グリッチ、ランダム揺れは読みやすさを損ないやすいため、既定の強さと設定可能な上限を
  控えめにする。表示後は音声終了後なので多少強い効果を許容できるが、新しいセリフが来た時点で打ち切る。

### AviUtl2パラメーターの実装状況

- 設定画面では時間範囲を扱わないため、2026-08-17に作成した暫定アニメーションGUIは廃止した。
  設定画面の大分類は「セリフ」「配役」「枠」の3項目へ戻す。
- アニメーション設定はAviUtl2オブジェクト側に置き、「表示前」「表示中」「表示後」の3グループとする。
  グループ内外で項目名は同じ名前空間になるため、全項目名に`前`、`中`、`後`を付ける。表示前／表示後は
  `前 種類`／`後 種類`、`前 時間`／`後 時間`、各`値1`～`値3`、表示中は`中 種類`、`中 速さ`、
  `中 値1`～`中 値3`を持つ。
- 種類には上記の全候補を登録し、先頭と既定値は`なし`とする。フィルタープラグインテーブルライブラリを
  経由して登録し、項目定義は専用ユニットへ分離する。
- 試作として`フェードイン`、`ふわふわ`、`フェードアウト`の3種類を実装した。他の候補は未実装。
  `ふわふわ`は`中 値1`を上下振幅px、`中 速さ`を1秒あたりの往復回数として使用する。
- 表示中の変換をセリフ開始から継続評価し、その結果へ表示前または表示後の透明度を合成する。
  セリフ終了時は表示内容を保持して表示後へ入り、別セリフが来た場合は直ちに打ち切って新しい表示前へ入る。
